The first Excel browser run failed because a six-column synthetic workbook fit its desktop viewport. The scroll check was corrected to constrain the viewport; both synthetic and real-reference runs then passed. Initial startup-test cleanup was denied by the sandbox; reruns with process-cleanup permission passed. A test-owned SQLite connection was also explicitly closed so Windows could clean its temporary directory.

The suite intentionally feeds a malformed automation rule to verify error isolation. Its logged `JSONDecodeError` is expected; the corresponding test passes. Openpyxl emits upstream Python 3.12 `utcnow()` deprecation warnings; these did not fail tests.

## Fixes and included changes

- Added the existing uncommitted Action Center, Excel calculation, private workbook/Word editing, shared template UI, exports and their regression suites to the reviewed project changes.
- Hardened employee management: changes persist in the existing SQLite connection, deletion is soft and invalidates sessions, duplicate names are normalized, and confirmation/role checks are server-side. Renames preserve task/document ownership and template grants, reserve the former identity, and retain workspace eligibility in both frontend and backend. Workflow imports cannot revive archived identities. A failed roster mirror write rolls back the database transaction.
- Kept deleted employees out of automatic task-start selection. Employee deletion does not remove tasks, time logs, alerts, documents or history.
- Fixed New Bill draft loss during live redraw, persisted success feedback, prevented duplicate submissions and ignored responses after a profile switch. Added a browser regression that forces the redraw before submission.
- Invalid JSON, nonnumeric/negative/oversized task IDs and invalid request lengths now return client errors rather than HTTP 500. Request bodies are bounded at 15 MB.
- Added system dark-mode variables using the existing neutral design. Existing cards, layouts and controls remain in place. Employee edit dialogs close on logout.
- Added `backend/launcher.py` and `/api/health`: configured-port validation, checkout identity, SQLite probe, startup locking, readiness checks, safe reuse, unrelated-port refusal and Chrome/default-browser selection. The backend binds its port before starting automation or loading demo records.
- Updated both BAT files to use the launcher, forward flags, preserve failure codes, work from other directories and handle paths with spaces. Existing Python/dependency discovery/install behavior remains.
- Replaced Git tracking of local deployment config/roster/workflow with sanitized `.example.json` files. Local originals remain intact. Fresh checkouts create local files from examples and require a privately configured Admin PIN or `SOMESH_ADMIN_PIN`; no default password was introduced.
- Updated README startup, database, environment, BAT, safety and testing instructions; added `tools/audit_live.cjs` for repeatable non-destructive verification.

## Architecture and remaining limits

- The configured database is **SQLite**, not MySQL. There is no MySQL integration to verify, and this audit did not introduce a second database.
- Attendance registers exist as workflow tasks and editable documents. There is no standalone attendance/leave register. Time calculations and lunch restrictions were tested.
- Assigned tasks support existing reassignment, status progression and confirmed deletion. Templates can be edited before assignment; arbitrary title editing of an existing assigned task is not implemented by the original application.
- Employee login retains trusted-office profile selection, while Admins require a PIN. Tests verify the existing permission model; individual employee passwords were not added.
- SMTP, Gather webhooks, ntfy and remote workflow feeds were inspected as optional integrations but not exercised against external production services. Python/dependency auto-install branches were inspected; the installed-Python/dependency startup path was executed. macOS/Linux and Docker launches were not executed on this Windows audit.
- Local deployment settings had been committed before this audit. They are removed from the new repository tree, but earlier Git history is unchanged. Rotate any previously published real credentials; this audit does not rewrite remote history.
- Git target: existing `origin`, branch `feature-automation-rules`. The final response records the resulting commit and the separately checked remote hash. No force push is used.
